PHARMACY MANAGEMENT SYSTEM — CANONICAL REACT NATIVE HANDOFF
=============================================================

Read this file instead of reading the backend source. It is the complete API
contract and frontend implementation brief for the currently implemented
Spring Boot backend as of 2026-10-09.

This is a REST/JWT API for authentication, RBAC administration, employees,
catalogue data, batch-level inventory, purchase orders, invoices, supplier
payments, audit logs, dashboard metrics, and a development-only payment
terminal simulator. There is no sales/POS domain yet; see "Not implemented".


1. FRONTEND STACK AND PROJECT BOOTSTRAP
---------------------------------------

Build a React Native app with Expo + TypeScript. Recommended packages:
  - expo-router or React Navigation
  - @tanstack/react-query for remote state
  - expo-secure-store for JWT storage
  - react-hook-form + zod for forms
  - a UI system of choice (NativeWind, React Native Paper, Tamagui, etc.)

Suggested project layout:
  app/(auth)/login.tsx
  app/(app)/(tabs)/dashboard.tsx
  app/(app)/medicines/*, suppliers/*, employees/*, inventory/*, purchases/*
  app/(app)/settings/{users,roles,permissions}.tsx
  src/api/client.ts, src/api/types.ts, src/api/*.ts
  src/auth/AuthProvider.tsx, src/auth/permissions.ts
  src/components/{FormError,EmptyState,ConfirmDialog}.tsx

Use a public Expo environment variable; never hardcode an IP address in code:
  EXPO_PUBLIC_API_BASE_URL=http://10.0.2.2:8080

Base URL by runtime:
  Android emulator: http://10.0.2.2:8080
  iOS simulator:    http://localhost:8080
  Physical device:  http://<computer-LAN-IP>:8080

All routes below are relative to API_BASE_URL and start with /api. All request
and response bodies are JSON. Set Content-Type: application/json only when a
request has a JSON body.

Backend local prerequisites (for the developer running it): PostgreSQL,
DB_PASSWORD, JWT_SECRET (32+ characters), and optional INITIAL_ADMIN_* env
variables. Flyway migrations run on startup. API documentation is available at:
  http://<host>:8080/swagger-ui.html


2. TOKEN SECURITY AND AUTHENTICATION
------------------------------------

Public endpoints:
  POST /api/auth/login
  POST /api/auth/logout
  GET  /v3/api-docs/** and /swagger-ui/** (documentation only)

Every other /api endpoint is protected. Send exactly:
  Authorization: Bearer <access-token>

Never store the token in AsyncStorage, Redux persistence, logs, analytics,
navigation parameters, or error reports. Use Expo SecureStore keys:
  accessToken
  accessTokenExpiresAt   (epoch milliseconds)
  currentUser            (optional cache only)

LOGIN
-----
POST /api/auth/login
Body:
{ "username": "admin", "password": "your-password" }

Success (200):
{
  "token": "eyJ...",
  "tokenType": "Bearer",
  "expiresIn": 86400,
  "user": {
    "id": "uuid",
    "username": "admin",
    "employeeId": null,
    "roles": ["OWNER"],
    "permissions": ["DASHBOARD_VIEW", "MEDICINE_VIEW"]
  }
}

Notes:
  - username also accepts the account email.
  - expiresIn is in seconds; persist Date.now() + expiresIn * 1000.
  - employeeId currently returns null even for a linked employee. Do not use it
    for navigation or authorization.
  - There is no refresh-token endpoint. On expiration, clear secure storage and
    require login again.

SESSION RESTORATION
-------------------
1. Read accessToken and accessTokenExpiresAt from SecureStore.
2. If either is missing or expired, show the login stack.
3. Otherwise call GET /api/auth/me with Bearer token.
4. On 200, replace cached currentUser with the response and show the app.
5. On any 401, clear all auth storage and reset to Login.

GET /api/auth/me returns only the user object from login (not a token):
{ "id":"uuid", "username":"admin", "employeeId":null,
  "roles":["OWNER"], "permissions":["..."] }

POST /api/auth/logout returns 204 with no body. JWT logout is client-side:
call it if convenient, then always delete the three secure-storage values.

GLOBAL HTTP RULES
-----------------
  400: show field-level errors when `errors` exists.
  401: exactly once, clear auth and navigate to Login.
  403: show "You do not have permission to perform this action".
  404: show a missing/deleted-record message and invalidate stale queries.
  409: show the backend `message` (duplicate or business rule violation).
  5xx: show a generic retryable error; never expose a stack trace.

Do not implement a client-side permission check as security. Use permissions to
hide/disable controls for clarity; the backend is authoritative and may return
403 anyway.


3. COMMON TYPES, PAGINATION, ERRORS, ENUMS
------------------------------------------

All IDs are UUID strings. Dates use YYYY-MM-DD. Timestamps are ISO-8601 UTC.
Amounts and quantities are JSON numbers. Format currency for display; avoid
floating-point arithmetic for authoritative business totals.

All paginated endpoints return:
{
  "content": [ ... ],
  "page": 0,
  "size": 20,
  "totalElements": 42,
  "totalPages": 3
}
Use page=0 based pagination. Pass sort as `field,asc` or `field,desc`.

Standard handled error response:
{
  "timestamp": "2026-10-09T12:00:00Z",
  "status": 400,
  "error": "VALIDATION_ERROR",
  "message": "Invalid request",
  "path": "/api/medicines",
  "errors": { "name": "must not be blank" }
}

Enums:
  RecordStatus: ACTIVE | INACTIVE
  EmployeeStatus: ACTIVE | INACTIVE | ON_LEAVE | TERMINATED
  DosageForm: TABLET | CAPSULE | SYRUP | INJECTION | CREAM | OINTMENT |
              DROPS | POWDER | SUSPENSION | OTHER
  MovementType: PURCHASE | SALE | SALE_RETURN | PURCHASE_RETURN |
                ADJUSTMENT_IN | ADJUSTMENT_OUT | DAMAGE | EXPIRED | TRANSFER
  PurchaseOrderStatus: DRAFT | PENDING_APPROVAL | APPROVED | ORDERED |
                       PARTIALLY_RECEIVED | RECEIVED | CANCELLED
  PaymentStatus: UNPAID | PARTIALLY_PAID | PAID
  PaymentMethod: CASH | UPI | CARD | BANK_TRANSFER | CHEQUE | OTHER

Render enum labels by replacing `_` with a space and title-casing. Do not send
arbitrary strings; send exactly the enum literals above.

INVENTORY ALERTS AND FEFO
GET /api/inventory/expired (STOCK_VIEW)
GET /api/inventory/expiring?days=30 (STOCK_VIEW; days >= 1)

{ "id":"batch-uuid", "medicineId":"medicine-uuid", "batchNumber":"P001",

16. API CLIENT REFERENCE
------------------------

Use one fetch wrapper and React Query hooks. The wrapper must add the bearer
token, deserialize the standard error response, and invoke one centralized 401
logout handler. Example shape:

type ApiError = { status: number; error?: string; message?: string;
  errors?: Record<string, string>; path?: string };
type PageResponse<T> = { content:T[]; page:number; size:number;
  totalElements:number; totalPages:number };

async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  const token = await SecureStore.getItemAsync("accessToken");
  const response = await fetch(`${API_BASE_URL}${path}`, {
    ...init,
    headers: {
      Accept: "application/json",
      ...(init.body ? { "Content-Type": "application/json" } : {}),
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...init.headers
    }
  });
  if (!response.ok) {
    const body = await response.json().catch(() => ({}));
    throw { status: response.status, ...body } as ApiError;
  }
  if (response.status === 204) return undefined as T;
  return response.json() as Promise<T>;
}

React Query invalidation guidance:
  - Medicine/category/manufacturer change: invalidate medicines + master lists.
  - Batch adjustment/receiving: invalidate batches, stock movements, inventory
    alerts/summary/FEFO, dashboard, medicine lists as appropriate.
  - Purchase update/approve/receive: invalidate purchases, purchase detail,
    batches, movements, dashboard, invoices as appropriate.
  - Supplier payment: invalidate supplier payments, invoice(s), dashboard.
  - RBAC change: invalidate users/roles/permissions and refresh /auth/me when
    changing the active user indirectly.
